# 验证范围

更新日期：2026-10-21；功能版本：0.4.0。本次为验证说明补充，运行脚本和发行包未变。以下分开记录隔离测试、初始引擎测试和后续双界面测试，不将不同层次的证据混为一项。

## 公开隔离测试

`python -m unittest discover -s tests -v` 执行 33 项测试，使用合成模型资料和临时目录，覆盖：

- 两种全局范围、三个参数分别或组合修改，未指定字段保留。
- 全局覆盖与单模型设置的转换、无法保留的计数语义拒绝。
- 默认压缩恢复、刷新后默认值跟随新资料。
- 新模型继承全部模型比例、单模型选择优先。
- 历史记录迁移、目录被手动修改、模型消失、上限变化的冲突检测。
- 预览无配置写入、备份恢复、后续编辑不被覆盖、中文 CLI 参数。
- 内置导出命令及失败处理（模拟子进程，不下载或调用真实模型）。

发布检查另外核对元数据、引用路径、私密文件排除、个人路径及常见凭据格式，并检查打包清单。它不是完整安全审计，也不等同于官方技能校验器。

CI 在 Windows 和 Python 3.11、3.12、3.13 上执行隔离测试、发布检查与打包；各次是否通过以 GitHub Actions 结果为准，不将计划中的矩阵当作已通过结果。

## 真实运行证据（发布整理前）

环境：Windows、本机 Codex `0.163.0-alpha.10.2` app-server，已有登录账号，临时 ephemeral 会话。8 个正式模型回合完成，观察到 2 次自动压缩开始及完成事件。

| 项目 | 实际证据 | 结论 |
|---|---|---|
| 单模型窗口及比例 | 原始窗口 600000、比例 90%；运行 `tokenUsage.modelContextWindow = 540000` | 该进程读取并使用设置 |
| 全部模型配置方式 | 原始窗口 64000、比例 80%；运行窗口 51200 | 该方式在测试模型上生效 |
| 内置资料刷新 | 实际目录预览及应用后，真实请求仍报告 51200 | 刷新后保留所测选择 |
| 全局压缩阈值 | 19041；上一回合使用量 35552；下一回合出现 `contextCompaction` 完成 | 观察到自动压缩 |
| 单模型压缩阈值 | 19000；上一回合使用量 20532；下一回合出现压缩完成 | 观察到自动压缩 |
| 恢复默认压缩 | 同样窗口、比例和内容，恢复后超过旧 19000 阈值的两个回合均无提前压缩 | 旧低阈值已解除；未测试默认触发点 |
| 原配置恢复 | 配置按原字节恢复，测试自定义目录移除；新请求窗口 258400 | 配置恢复及恢复后请求通过 |
| 技能发现 | 本机 `skills/list` 强制重读找到技能，无该技能解析错误 | 实测安装目录可发现 |

上述模型回合使用 `gpt-6-luna`；另外对其他目录条目做了配置字段保持检查，但未逐个模型发起真实请求。不是只根据模型回答或脚本推算判断生效。

首次记录程序有输出参数冲突，导致一次尝试在响应后记录失败；修正记录程序后重新完成正式测试。该次尝试另有 2 个成功响应，不计入上述 8 回合。

原始事件日志及配置备份由维护者私下保留，**不公开上传**，以免泄露路径、配置、账号元数据和会话内容。因此历史实机结果是维护者报告，读者不能仅靠本仓库复核全部原始事件。公开测试可独立复现，但不证明服务端行为。

## Work Local 与 Codex Local 双界面验证

后续由用户手动分别切换到 Work Local、Codex Local，并在各界面新建聊天。维护者切换同一用户 `config.toml` 的全局窗口，核对真实会话日志。该验证补齐了初始测试没有分别经过两个界面的缺口。

环境为 Windows、本机 Codex 引擎 `0.163.0-alpha.11`；四个新聊天均使用 `gpt-6-luna`、low 推理强度、同一工作目录，模型目录有效比例为95%。

| 共享原始窗口 | Work Local 实际可用窗口 | Codex Local 实际可用窗口 |
|---|---:|---:|
| 500000 | 475000 | 475000 |
| 600000 | 570000 | 570000 |

四个回合均正常完成。会话记录的 `session_meta.originator` 分别为 `codex_work_desktop` 和 `Codex Desktop`，窗口取自 `event_msg` 的 `token_count.info.model_context_window`。没有用模型自述或聊天标题作为窗口证据，也不是仅由测试程序给请求添加模式标记。

两轮之间没有重启桌面应用；修改后新建的两种模式聊天均跟随共享配置变化。测试结束后两次事务逆序恢复，配置SHA-256与测试前一致，自定义目录状态也恢复。用户创建的测试聊天保留。

这证明本轮环境下**共享配置对两个模式的新聊天均有效**。不代表旧聊天立即改变，不覆盖全部模型与客户端版本，也没有在这四个回合中重复触发自动压缩。当前技能的范围仍为全部模型或指定模型，不提供按界面模式分别持久保存窗口的功能。

### 手动复测步骤

1. 保存原始配置及事务备份，确认两个模式选择同一模型、同一目录，记录有效比例。
2. 将共享原始窗口设为500K，分别从 Work Local 和 Codex Local 界面新建聊天，发送一个要求简短回复、不使用工具的标记。
3. 核对会话归属和真实 token 使用事件中的窗口；95% 比例下预计为475K。
4. 将共享窗口改为600K，再分别新建聊天，预计为570K；保留两轮结果对照。
5. 逆序恢复两次事务，核对配置与原始字节一致。若有并行配置编辑，先处理冲突，不覆盖后续修改。

复测会真实调用模型，需使用者授权。原始日志、账号标识、会话ID和个人路径不随本说明公开；这是维护者对用户手操测试的脱敏结果报告。

## 未验证与限制

- 初始压缩测试使用新启动的本机引擎；后续双界面窗口测试使用用户新建的桌面聊天，两轮间未重启应用。两组证据都不能证明已打开的旧聊天自动切换设置。
- 未对全部模型、所有 Codex 版本、macOS/Linux 或其他客户端做真实调用验证。
- 未发送 60 万 token 长输入，不能证明服务端接受该长度。
- 未把窗口填满以触发恢复后的默认压缩阈值。
- 账户缓存可能在客户端启动时刷新；仅配置及测试目录按事务恢复，没有声称整个用户目录完全不变。
- 官方 `quick_validate.py` 当时因本机缺少 PyYAML 未完成；YAML 使用已有解析器检查，并补充了真实技能发现。没有把官方校验器记为通过。

## 复测原则

默认只运行公开隔离测试。真实复测会写用户配置、发起模型请求并可能消耗额度，需要取得使用者对这些动作的授权。先保存配置摘要及备份；用短期测试进程观察实际 token 使用和压缩事件；结束后逆序恢复并核对原始字节。不要将 CI 改成自动调用维护者账户。
